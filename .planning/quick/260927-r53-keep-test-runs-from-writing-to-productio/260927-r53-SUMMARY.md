# Quick Task 260927-r53: Keep test runs from writing to production logs Summary

Session-scoped autouse pytest fixture repoints `configure_logging()`'s default `log_dir` at a per-session tmp directory via `__defaults__` patching, so no test run appends to the live bots' shared `logs/bot.log` — guarded by a new regression test proven red-before-fix and red-under-mutation.

## What Was Built

**Task 1 (RED):** Added `test_bare_configure_logging_does_not_target_production_log` to `tests/safety/test_logger.py`. Calls `configure_logging()` with no arguments and asserts none of the root logger's handler `baseFilename` values equal `os.path.abspath("logs/bot.log")`.

**Task 2 (GREEN):** Added `_isolate_bot_log` — a `scope="session", autouse=True` fixture in `tests/conftest.py` — that uses `pytest.MonkeyPatch.context()` to set `bot.safety.logger.configure_logging.__defaults__` to `(tmp_path_factory.mktemp("logs"), logger._DEFAULT_LEVEL)` for the whole test session. This is a function-object patch, not a module-attribute or constant patch, because `bot/main.py` and `bot/options/service.py` import `configure_logging` by name and hold the same function object — only patching `__defaults__` on that object reaches those callers too. `bot/safety/logger.py`, `bot/main.py`, and `bot/options/service.py` were not touched (production code byte-for-byte unchanged).

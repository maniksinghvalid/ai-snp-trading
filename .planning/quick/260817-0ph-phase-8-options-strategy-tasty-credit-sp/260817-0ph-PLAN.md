Create `bot/options/strategy.py` — **pure functions only**: no I/O, no clock reads, no SDK, no logging side effects. Module docstring naming the exports and stating the purity contract (design D7: the Phase 9 backtester replays these).

Implement exactly these signatures (from the design's "Key signatures" block — do not rename parameters):

`is_monthly_expiry(expiry: date) -> bool` — True when `expiry` is the third Friday of its month.

`option_dte(expiry: date, today: date) -> int` — calendar days, `(expiry - today).days`.

`pick_expiry(expiries: list, today: date, cfg) -> Optional[date]` — `expiries` is a list of `(expiry_date, dte)` tuples. Drop entries with `expiry_date < today` and entries whose dte is outside `[cfg.min_dte, cfg.max_dte]`; return `min(candidates, key=lambda e: (abs(dte - cfg.target_dte), cfg.prefer_monthly and not is_monthly_expiry(expiry)))` — i.e. closest to target first, monthly wins ties only when `cfg.prefer_monthly`; `None` when nothing is in range.

`passes_entry_gate(u: dict, cfg) -> bool` — `u` has `ivr_pct`, `ivp_pct`, `change_pct` (IVR already in percent units, 0–100; the ×100 conversion is the service's job in Wave 4). Threshold is `cfg.ivr_min`, lowered to `cfg.fear_ivr_min` when `u["change_pct"] <= -cfg.fear_drop_pct` (sell into fear). Pass requires `ivr_pct >= threshold`; when `cfg.ivp_min` is not None it additionally requires `ivp_pct >= cfg.ivp_min` (dual gate against IVR outlier skew). Missing/None `ivp_pct` with `ivp_min` set fails closed.

`leg_is_liquid(row: dict, cfg) -> bool` — row has `bid`, `ask`, `open_interest`. False unless `bid > 0`, `open_interest >= cfg.min_open_interest`, and `(ask - bid) / mid * 100 <= cfg.max_spread_pct_of_mid` where `mid = (bid + ask) / 2` (guard mid <= 0 → False).

`pick_strikes(rows, underlying_px, structure, cfg) -> Optional[dict]` — `rows` are per-contract dicts (`code`, `right` 'C'/'P', `strike`, `delta`, `bid`, `ask`, `open_interest`); `structure` is `"iron_condor"` or `"put_credit_spread"`. Wing width in dollars is `underlying_px * cfg.wing_width_pct_of_underlying / 100`. Put side: short = the put whose `abs(delta)` is closest to `cfg.short_delta`; long wing = the **listed** put strike closest to `short_strike - width` **and at least one listed strike below the short** (never the same strike). Iron condor adds the symmetric call side (short call = call `abs(delta)` closest to `short_delta`; long call = listed call strike closest to `short_strike + width` and at least one strike above). Return `None` if any selected leg fails `leg_is_liquid`. `credit = sum(short mids) - sum(long mids)`; `width = max(vertical widths)` (max, not sum — conservative for unequal IC snaps); return `None` when `credit < cfg.min_credit_to_width * width`. On success return `{"legs": [...], "credit": credit, "width": width}` where legs are dicts `{"code", "right", "strike", "side", "mid"}` ordered **long wings first, then shorts** (this is the safe OPEN order Wave 3's `LegExecutor` consumes: buy protection before selling risk).

`size_position(width, credit, cfg, open_max_loss_total) -> int` — `risk = (width - credit) * 100` (per spread, 100 multiplier); return 0 when `risk <= 0`. `qty = floor(cfg.sizing_equity_usd * cfg.max_risk_per_trade_pct / 100 / risk)`, then cap with `floor((cfg.sizing_equity_usd * cfg.max_bp_usage_pct / 100 - open_max_loss_total) / risk)`; return `max(min(qty, cap), 0)`. Use `math.floor` explicitly (established convention, `bot/risk` T-03-08).

`mark_spread(legs, quotes) -> float` — cost-to-close per spread: `sum(mid for SELL legs) - sum(mid for BUY legs)`, mids taken from `quotes[code]` (`{"bid","ask"}`).

`manage_decision(mark, credit, dte, cfg) -> Optional[str]` — evaluate strictly in this order, returning the first hit: `dte <= cfg.assignment_guard_dte` → `"assignment_guard"`; `credit - mark >= cfg.profit_target_pct_of_credit / 100 * credit` → `"profit_target"`; `cfg.stop_loss_credit_multiple is not None and mark - credit >= cfg.stop_loss_credit_multiple * credit` → `"stop_loss"`; `dte <= cfg.manage_dte` → `"dte_exit"`; else `None`.

Every threshold reads from `cfg` — no literal strategy numbers (the only literals permitted are the 100 contract multiplier and the /100 percent conversions).

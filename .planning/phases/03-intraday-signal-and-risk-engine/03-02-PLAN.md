<objective>
Build the `SignalEngine` — the orchestrator that takes a closed `BarEvent` from `BarAggregator`, feeds the already-built `TrendJoinLong.passes_intraday_filters()` (I1 above premarket high, I2 above HOD, I3 RVOL ≥ 2.0), and composes four independent gates — the 10:05–15:30 ET entry window, the 5-concurrent-position cap (broker truth), the daily new-entry cap, and the D-03 missing-premarket-high guard — emitting a `SignalEvent` only when every gate passes.

Purpose: This is the decision layer for SIG-03 and SIG-04 plus RISK-04/RISK-05's gates. Each gate is independent (RESEARCH success criterion #3 requires the daily cap to bind even when the concurrent cap has free slots), so they must be evaluated separately and short-circuit with a specific logged reason. All thresholds come from `StrategyConfig` — zero literals (CFG-01).

Output: `bot/signal/signal_engine.py` and the fleshed-out `tests/signal/test_signal_engine.py` covering every gate and the entry-window boundary table.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SignalEngine → broker (get_positions) | Concurrent-cap decision depends on broker-truth position count; a stale/empty read could under-count and allow an over-limit entry |
| SignalEngine → StateStore (daily_trade_count) | The over-trading guard reads a persisted counter; a burst of intents in one bar must not blow past the cap before any fill registers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering / Integrity | Daily-cap over-trading guard (burst of intents in one bar — D-09) | mitigate | Gate on `filled_count + in-memory pending tally`; increment the pending tally at intent emission so a burst within one bar is bounded BEFORE any fill registers (D-09 burst guard) — `test_daily_cap_blocks_after_max` proves it |
| T-03-05 | Spoofing / Integrity | Concurrent-cap bypass via stale position read | mitigate | Concurrent count sourced from `gateway.get_positions()` broker truth (not an in-memory guard); RESEARCH Pitfall 4 flags `refresh_cache` for the live variant so the count is current — `test_concurrent_cap` proves the gate binds |
| T-03-06 | Elevation of Privilege | Phase 3 corrupting the fill-authoritative counter | mitigate | SignalEngine NEVER writes `daily_trade_count` (read-only); only Phase 4 increments it at fill (D-08) — source assertion verifies no UPDATE/INSERT on the table (Pitfall 5) |
| T-03-11 | Integrity | Duplicate entry via re-signal on a code with a live pending intent (D-10) | mitigate | Re-entry gate requires BOTH broker-flat (`get_positions()`) AND no `pending_intents` PENDING row for the code; a live pending intent blocks re-signal — `test_reentry_blocked_by_pending_intent` proves it |
| T-03-12 | Integrity | Trading on a stale/absent premarket-high reference (D-01/D-03) | mitigate | `fetch_premarket_highs` freezes the highs from one batched `get_market_snapshot` at 09:30 and EXCLUDES any code with `pre_high_price <= 0` (never falls back to prior-day high) so no entry fires on a missing breakout reference |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No new packages this phase (Package Legitimacy Audit empty); no install task to gate. |
</threat_model>

# Phase 07.1: Close gap: RISK-TICK-STOP — wire gateway into PositionManager - Context

**Gathered:** 2026-07-06
**Status:** Ready for planning
**Source:** Audit Express Path (`.planning/v1.0-MILESTONE-AUDIT.md` Gap 1, discovered by `gsd-integration-checker` during the v1.0 milestone audit) — discuss-phase skipped because the root cause, exact fix location, and fix shape are already fully diagnosed with file:line evidence; there is no open design question left to discuss.

<domain>
## Phase Boundary

`PositionManager` has supported an optional `gateway=None` constructor kwarg since Phase 7 (07-03-PLAN.md), and `arm_stop_protection()` already implements both the broker Stop-Market path (D-01) and the quote-tick fallback (D-02) correctly when `self._gateway` is set. The bug is entirely in *production wiring*: `bot/main.py`'s real `PositionManager(...)` construction (lines 100-111) never passes `gateway=`, so `self._gateway` is `None` on every live/paper run and `arm_stop_protection()` silently no-ops (manager.py:265-266). Phase 07's own `VERIFICATION.md` marked RISK-TICK-STOP satisfied because it checked class-level wiring in isolation (a manually-injected `PositionManager(gateway=...)` in a unit test), not the actual production construction call — that's how this shipped broken and passed verification.

This phase's boundary is narrow: wire `gateway` into the real construction path, and add a regression test that drives *that real path* (not a hand-built instance) so this class of bug — correct class, wrong wiring — cannot silently regress again. No changes to `arm_stop_protection()`, `place_stop_order`, `subscribe_quote`, or the bar-close backstop (D-03) logic itself — that code is correct and already tested at the unit level.

</domain>

<decisions>
## Implementation Decisions

### Root cause (confirmed against current code, 2026-07-06)
- `bot/position/manager.py:131-160` — `PositionManager.__init__` accepts `gateway=None` and stores `self._gateway = gateway`. Correct, unchanged.
- `bot/position/manager.py:265-266` — `arm_stop_protection()` returns immediately `if self._gateway is None`. Correct, unchanged — this is the intended fail-safe (falls back to the bar-close backstop), not a bug in itself.
- `bot/main.py:100-111` — the real `PositionManager(store=..., engine=..., cfg=..., strategy=..., on_entry_alert=..., on_exit_alert=...)` call. **`gateway=` is absent from this call.** `gateway` is already a local variable in scope (constructed at `bot/main.py:75` and passed into `ExecutionEngine`, `SignalEngine`, `RiskEngine`, and `TradingBot` already) — this is a one-argument omission, not a missing dependency.
- No code anywhere late-binds `position_manager._gateway` after construction (confirmed: grepped `bot/main.py` and `bot/service/bot.py`).

### Fix shape
- **Primary fix (required):** add `gateway=gateway,` to the `PositionManager(...)` call in `bot/main.py` (around line 100-111), alongside the existing kwargs.
- **Precedent for an alternative/supplementary approach:** `bot/service/bot.py::_do_startup_wiring` (line ~180) already late-binds `self._position_manager._bar_buffer = self._bar_agg._bar_buffer` after construction, for a value that isn't known until the loop starts. `_gateway` does NOT have this excuse — `gateway` is available at construction time in `bot/main.py`, so the direct constructor-kwarg fix is correct and sufficient. Do not introduce a redundant late-bind for `_gateway` unless the executor finds a concrete reason the constructor-kwarg fix doesn't hold (e.g., test fixtures constructing `PositionManager` before `gateway` exists) — if so, mirror the exact `_bar_buffer` late-bind pattern in `_do_startup_wiring`, don't invent a new mechanism.
- **Do not touch:** `arm_stop_protection()`, `place_stop_order`, `subscribe_quote`, quote-tick callback wiring, or the bar-close FSM (D-03) — all already correct and tested in isolation.

### Regression test requirement (the part that actually prevents recurrence)
- The existing Phase 7 tests are insufficient because they construct `PositionManager(gateway=mock_gateway)` directly — that's what let this ship broken. The new test MUST exercise the real production construction path: either import and call `bot.main`'s construction sequence (or the smallest extractable slice of it) and assert `position_manager._gateway is not None`, or construct `TradingBot` the way `bot/main.py` does and assert the wiring holds.
- Stronger version (prefer if feasible without excessive mocking): assert that calling `arm_stop_protection()` through the real-construction `position_manager` actually calls `gateway.place_stop_order` / `gateway.subscribe_quote` (mocking only the gateway's I/O, not the wiring) — this is closer to what the audit's integration checker actually verified was broken.
- This is a `type: tdd`-eligible fix: write the failing regression test against current `bot/main.py` first (it should fail, proving it would have caught this bug), then apply the one-line fix, then confirm green.

### Non-goals / explicitly out of scope
- No changes to RVOL-TOD, circuit breaker, or exit-model code (Phase 7 waves 1/3/4) — unrelated to this gap.
- No changes to `arm_stop_protection`'s internal logic, `use_broker_stop_orders` config flag behavior, or the quote-tick fallback itself.
- Not required to fix the Tier 2/Tier 3 tech debt or Phase 6 backtester gaps also listed in `v1.0-MILESTONE-AUDIT.md` — those are separate, already-tracked, out of scope for this phase.
- Not required to update `07-VERIFICATION.md`'s original (incorrect) SATISFIED verdict — that historical record stays as-is; this phase's own `VERIFICATION.md` is what re-establishes the true state, and `REQUIREMENTS.md`'s traceability row has already been corrected to reflect this gap.

</decisions>

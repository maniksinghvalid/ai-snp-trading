<objective>
Lay the Wave-0 foundation for Phase 4 (new bot/execution + bot/position packages, the execution config block, migration 0004, and all failing test stubs) AND implement the pure, broker-independent PositionState FSM that drives every exit rule: 1/3 partial at 0.75R (POS-01), breakeven at 1.0R (POS-02), and the never-loosen 5m swing-low trail after breakeven (POS-03). Every transition is judged on the bar CLOSE (D-02/D-03) and every threshold is read from rules.json (CFG-01).

Purpose: The FSM is the strategy's risk brain. It implements the D-01 synthetic, bot-monitored stop (no resting broker stop) -- exits are decided in-process on the bar close (D-02), never by a native broker stop order. It must be provably correct in isolation -- synthetic Fill/Bar events only, zero broker dependency -- before PositionManager (04-02) and ExecutionEngine (04-03) build on it. Establishing the shared scaffold here (packages, config, migration, test stubs) gives the parallel Wave-2 plans a stable, conflict-free base.

Output: New packages bot/execution/ and bot/position/; FillEvent dataclass; PositionPhase enum + PositionState FSM dataclass with pure on-close transition methods; execution block in rules.json + schema + StrategyConfig; migration 0004; new test packages with failing stubs for all 10 requirements; conftest fixtures for synthetic Fill/Bar events.

Risk distance R = entry_price - initial_stop. Logic, judged on the CLOSE only:
  - ACTIVE: if close <= trail_stop -> STOP_OUT; elif close >= entry_price + cfg.partial_profit_trigger_R * R -> PARTIAL (sell floor(remaining_quantity * cfg.partial_profit_fraction)) -> phase PARTIAL_TAKEN (POS-01, D-03).

The actual swing-low value is supplied by the caller (PositionManager computes it via compute_swing_low_2_2 in 04-02); the FSM only applies the max() ratchet. NO hardcoded R-thresholds or fraction literals -- all come from cfg (CFG-01).

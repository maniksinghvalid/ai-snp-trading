<objective>
Wire the safety-critical lifecycle edges that make the bot survivable and unattended: (1) startup reconciliation that lets broker truth win, adopts orphan positions with a derived stop, and resumes known positions with a never-loosened stop (POS-05/D-09/D-10/D-11); (2) a broker-verified duplicate-order guard (EXEC-04); (3) the calendar-aware 15:51-ET force-close that escalates marketable limits until flat and never carries overnight or uses a market order (POS-04/D-08); and (4) kill-switch flush of in-flight FSM state (SAFE-04). This is the plan that connects ExecutionEngine and PositionManager into a closed, restart-safe loop.

Purpose: These are the invariants that prevent the two worst failure modes -- duplicate/runaway entries after a crash, and risk left unmanaged (a loosened stop, an orphan position, or a position carried overnight). Each is broker-verified, not memory-only.

Output: filled-in startup_reconcile/reconcile_once drift resolution in the gateway; ExecutionEngine.consume_intent broker-verified duplicate guard (EXEC-04), PositionManager force_close_all + get_force_close_time_et, and flush_all registration; green tests for force-close half-day (POS-04) and restart reconciliation including orphan adoption and never-loosen (POS-05); duplicate-guard test (EXEC-04).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| broker positions -> in-memory FSM (restart) | broker truth must override stale in-memory/persisted state; a wrong override re-enters or loosens risk |
| pending_intents -> entry placement (restart) | a PENDING intent re-processed after a crash can double-enter |
| force-close clock -> exit placement | the EOD invariant ("flat by close") must hold; a missed/loose force-close carries overnight |
| SIGINT/sentinel -> state flush | shutdown must not drop in-flight FSM state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-16 | Tampering | restart double-entry | mitigate | pending_intents reconciled against get_positions() AND get_order_status() before resuming; EXEC-04 broker-verified duplicate guard blocks a second entry (POS-05/D-09, Pitfall F) |
| T-04-17 | Tampering | stop loosening on restart | mitigate | known positions resume persisted trail_stop; updates use max(persisted, new_swing_low) only (D-11); test asserts a lower swing-low does not lower the stop |
| T-04-18 | DoS | orphan position left unmanaged | mitigate | orphan adopted ACTIVE with compute_initial_stop stop, re-subscribed, and force-closed -- never left unmanaged (D-10) |
| T-04-19 | DoS | position carried overnight / runaway force-close | mitigate | force_close_all escalates limits bounded by reaching remaining==0 and the bell; never a market order; loud force_close_stuck alert if stuck (D-08); calendar-aware time so it fires on half-days (POS-04) |
| T-04-20 | Spoofing | stale broker state during reconciliation | mitigate | get_positions/order_list_query called with refresh_cache=True (Pitfall B) |
| T-04-21 | Tampering | in-flight state lost on shutdown | mitigate | flush_all persists every PositionState DB-first; registered with KillSwitch (SAFE-04) |

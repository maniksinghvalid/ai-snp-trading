<objective>
Build the PositionManager: the single owner of all PositionState objects. It consumes FillEvents from the ExecutionEngine (04-03) and closed-bar events from the BarAggregator, drives the pure FSM (04-01) through its transitions, and persists every transition to StateStore DB-first (Pitfall G). On entry fill it writes the fill-authoritative daily_trade_count and resolves the originating pending_intents row (Phase-3 D-08/D-12). It computes the 5m swing-low trail via compute_swing_low_2_2 and applies the never-loosen ratchet (POS-03/D-11). It reconstructs all positions from StateStore on restart (POS-05) and flushes in-flight state on kill-switch.

Purpose: PositionManager is the orchestration seam between fills, bars, the FSM, and durable state. Persisting DB-first and reconciling by order_id are the load-bearing safety invariants — a partial exit must never be misread as a full stop-out (EXEC-05), and a crash mid-transition must never corrupt state.

Output: bot/position/manager.py (PositionManager class) with on_fill, on_bar, transition handlers, DB-first persistence, daily-count/pending-intent reconciliation, restart reconstruction, and flush_all; green manager unit tests for fill/bar processing and restart reconstruction (POS-05).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ExecutionEngine fills -> PositionManager | FillEvents (broker truth about money/shares) cross into FSM state; mis-keying a fill corrupts position risk |
| in-memory FSM -> StateStore | every transition must land in durable storage atomically; a crash between memory and disk is a corruption window |
| BarAggregator buffer -> trail computation | swing-low input drives the stop; a lower recomputed swing must never loosen the stop |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Tampering | exit fill reconciliation | mitigate | Fills matched by order_id (entry_order_id/exit_order_id), never by qty -- a 1/3 partial exit is not misread as a full stop-out (EXEC-05, Pitfall C); test asserts remaining_quantity decrements correctly |
| T-04-06 | Tampering | FSM state on crash mid-transition | mitigate | DB-first write then in-memory mutation inside a single commit (Pitfall G); crash-sim test asserts the DB row is authoritative |
| T-04-07 | Tampering | trail_stop on bar update | mitigate | trail_stop = max(trail_stop, new_swing_low) only (D-11); never assigned a lower recomputed swing-low |
| T-04-08 | DoS | half-exited stop-out left unprotected | mitigate | CLOSED only when remaining_quantity == 0; remainder stays open so 04-03 keeps escalating the exit (Pitfall E) |
| T-04-09 | Information Disclosure | audit log of transitions | mitigate | append_audit records code/phase/qty/price/order_id only -- no credentials (SAFE-05) |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages this phase (04-RESEARCH Standard Stack); no install task exists |

<objective>
Build the cache-only CLI that drives the experimental engine: window resolution from one locked
table, a hard cache-presence guard that makes an accidental Massive fetch impossible, the
per-window/per-arm run loop that shares one feed and one day-grouping across all arms, report
writing with the five extra trade columns, and the `--tjl-regime` mode that day-filters the
existing TJL baseline instead of re-running the TJL harness.

Purpose: XSR-04 — every backtest in this phase must run cache-only with zero new Massive requests,
because the Phase 9 `warm-cache-pool` background process owns the shared 5 req/min free-tier
budget. The guard in this plan is the mechanism that guarantees it, not a convention anyone has to
remember.

Output: `backtester/experimental/run.py` + `tests/backtester/experimental/test_run.py`.

**Parallelism contract:** plan 10-02 executes in this same wave and creates
`backtester.experimental.{indicators,strategies,exits,engine}`. This plan MUST NOT import those
modules at module import time and its tests MUST NOT depend on them. Reach them through two
factory seams with function-local imports — `_build_engine(...)` and `_load_regime_labels(path)` —
which `test_run.py` monkeypatches. The signatures 10-02 commits to (use them verbatim inside the
seams):
- `Engine(frames, signals, params, feed, slippage, stop_fill, regime_fn=None)` with `.run(days) -> list[dict]` and `.gap_through_entries -> int`
- `build_frame(feed, code, params) -> DataFrame`, `group_by_day(feed, days) -> dict[str, list[dict]]`
- `ext2_signals(frame, params)`, `orb_signals(frame, params)`, `vwap_pb_signals(frame, params)`
- `weekly_regime(spy_daily) -> Series`, `regime_for_day(labels, day) -> str`
</objective>

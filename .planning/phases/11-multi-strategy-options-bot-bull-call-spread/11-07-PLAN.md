<objective>
Close the one BLOCKER verification gap of phase 11 (CR-01), the two review warnings the user
scoped in (WR-01, WR-05), and the two follow-ups the user approved after planning (EX-01,
Q-01). Each fix uses the shortest correct diff in the file that owns the behavior. Each has
a regression test that FAILS on 530667d and passes afterwards. The one exception is a
preservation test, called out in Task 3.

1. CR-01 (verification gap, BLOCKER). `_manage_position` only checks that each leg's code
   is a key in `quotes`. `strategy._as_float` then maps the SDK's literal 'N/A' (and None,
   '', NaN) to 0.0, so a single unquoted leg is marked at $0. That causes:
   - false profit-target exits;
   - a false unrealized loss that can trip the global $2,000 daily-loss breaker;
   - a buy-back priced near $0;
   - a `close_legs` ValueError that is swallowed and leaves the row in CLOSING with no alert.

   Fix: add the pure helper `_quote_ok`, gate `_manage_position` on it (it is the only
   consumer of `quotes`), and wrap `close_legs` in try/except so a failure reaches the
   existing NEEDS_ATTENTION branch.
2. Q-01 (approved follow-up). CR-01 alone would silently skip, every cycle, a position whose
   leg never gets a usable quote, including a position about to expire. Inside the
   assignment-guard window, the gate therefore escalates: NEEDS_ATTENTION plus an alert,
   instead of the silent skip.
3. EX-01 (approved follow-up; lifts the "execution.py frozen" constraint for close_legs
   only). `close_legs` sells the long wings even after a short buy-back failed, which leaves
   a naked short. New rule: a failed short blocks every long sell; a failed long does not
   block the other longs.
4. WR-01 (D-29 completion). D-29 checks only the strategy NAME. A position whose strategy
   still exists but whose structure KIND changed is decided with the other kind's config.
   The field it needs is None there, so `None / 100` raises TypeError every cycle and the
   position is never managed.
5. WR-05 (D-22 completion). BP headroom and the per-strategy concurrent count only count
   OPEN/OPENING rows. NEEDS_ATTENTION and CLOSING rows are still live broker exposure.

WR-01 interpretation (accepted by the user): the check compares structure KIND (debit
`bull_call_spread` vs any credit structure), not the exact type string. config._check_strategy
partitions the manage fields exactly this way. iron_condor and put_credit_spread share
`manage_decision` and use identical fields.

EX-01 call-site audit (done at planning time). There are three `close_legs` callers, and none
depends on longs being sold after a short failed:
- `open_position`'s entry unwind (execution.py l.208, aggressive=True) discards the return
  value.
- `service._manage_position` (l.930) treats False as NEEDS_ATTENTION plus an alert.
- `scripts/uat_options_probe.py` (l.234) treats False as NEEDS_ATTENTION.

For the entry unwind, EX-01 changes the leftover after a failed unwind from a naked short
into a defined-risk remainder. Its misleading "legs unwound" ABORTED report is pre-existing;
it is recorded as backlog item EX-02 and is out of scope.

Purpose: restore MSO-08, MSO-05 and MSO-07.
- MSO-08: the breaker is fed only real P&L; BP and concurrent caps count every live row; no
  cross-kind parameters are applied.
- MSO-05: `manage_decision_debit` only ever sees a real mark and its own kind's config.
- MSO-07: a close is booked CLOSED only when every leg closed; the realized math is unchanged.

Output: bot/options/service.py and bot/options/execution.py, plus 35 new test cases across
test_service.py (31) and test_execution.py (4). One legacy execution test is replaced, so the
suite grows by 34.

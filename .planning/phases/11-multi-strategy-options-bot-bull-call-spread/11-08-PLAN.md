1. **CR-02 (EX-02), BLOCKER.** `LegExecutor.open_position` discards the return value of `close_legs` during the entry unwind (execution.py l.209). A failed unwind therefore returns None, exactly like a clean one. `OptionsBot._try_open` (service.py l.835-850) then marks the row ABORTED and sends "legs unwound", which is false. ABORTED is not in `_ACTIVE_STATUSES` (l.92), so the stranded legs are invisible to BP headroom, the per-strategy concurrent count, `busy` and reconcile.
   - Fix: `open_position` returns False when the unwind is incomplete, and also when the unwind raises.
   - `_try_open` maps False to NEEDS_ATTENTION with a truthful alert and a distinct audit event. It returns the position so the current scan counts the row.
   - The operator probe (the only other `open_position` caller) is updated to honour the new contract.
2. **WR-06.** Q-01 escalates permanently on the first cycle with a bad quote inside the guard window. That includes the 09:35 ET first cycle and a failed 400-code snapshot chunk.
   - Fix: a per-position in-memory streak. Escalate at 3 consecutive counted cycles, or on the final manage cycle of the expiry session.
   - A snapshot outage is logged and never counted.
3. **WR-07.** `_quote_ok` accepts one-sided (bid=0) and arbitrarily wide quotes. That allows a false profit_target, which becomes a naked long plus NEEDS_ATTENTION, and a false daily-loss-breaker trip.
   - Fix: a stricter `_quote_markable` gate for every decision outside the guard window.
   - Inside the window the loose `_quote_ok` stays, because the decision there is always `assignment_guard` whatever the mark.

Design decisions (made at planning time; the executor must not re-decide them):

- **CR-02 signalling: `return None if unwound else False`.** This is the review's suggestion and the smallest change. It is the ONLY contract change in execution.py.
  - Why not an exception: `_scan_and_open` catches exceptions per underlying and `continue`s before `busy.add`. That would leave the row OPENING with no alert, which is a second bug to fix.
  - Why not a sentinel object: it adds a symbol that has to be imported in two places, for the same information.
- **CR-02 leg recording: record nothing new.** The NEEDS_ATTENTION row already carries every code that can be stranded, because `_try_open` inserts ALL leg rows before the first order is placed (l.803-816).
  - That is enough for `busy`, BP, the concurrent count and operator visibility.
  - The broker is the source of truth for quantities, and the alert names every code to check.
  - Exact per-leg remainders would need `open_position` to return per-leg unwind outcomes (a second contract change, which is forbidden). They would also need partial-quantity persistence, which is WR-08's defect class (deferred).
  - Residual: `max_loss_usd` is the full spread's max loss computed at entry. The stranded remainder always keeps every long wing (EX-01), so it is defined-risk. It can exceed the recorded figure by at most about one leg's premium × qty × 100; for a bull call this is the premium of the short that did not fill. Accepted as T-11-45.
- **WR-06 rule: N = 3 consecutive counted cycles, OR the final manage cycle of the expiry session.** These facts come from reading the schedule:
  - `options_manage` is an `IntervalTrigger(minutes=manage_interval_min=5)`, gated by `_is_rth_now` to `09:35 <= now < close − 5 min`. That is 76 cycles on a full day and 40 on a half day.
  - With `assignment_guard_dte: 1` (both shipped strategies) the window spans two sessions, about 150 cycles.
  - An OPEN position inside the window with a good quote closes on that cycle. So a position still OPEN there has had only bad or outage cycles, and N = 3 hands it to the operator 10 minutes after the first counted miss while riding out the 09:35 price-discovery gap.
  - The final-cycle trigger only matters when fewer than 3 counted cycles happen before expiry (a late start or restart on expiry day). There, "retry next cycle" would silently carry the position into expiry, so the rule escalates on the last cycle.
  - It is limited to `dte <= 0` because on the day before expiry a whole automated session still follows, and the streak carries overnight in memory. The `now + manage_interval_min >= _manage_cutoff(today)` test is conservative: a cycle delayed by the lock can make it fire one cycle early, which fails toward the human.
- **WR-07 width rule: `ask - bid <= max(_MARK_MAX_SPREAD_FRAC_OF_MID × mid, _MARK_MAX_SPREAD_FLOOR_USD) + 1e-9`, with 0.5 and $0.10 as named service.py module constants.** This is the review's formula.
  - The entry gate in both shipped strategies (rules_options.json) is `max_spread_pct_of_mid 5.0` or `max_spread_abs_usd 0.05`. The marking gate is 10× looser in % and 2× looser in $ because its job is to reject ABSURD quotes, not illiquid-but-real ones. A leg that passed a 5% / $0.05 entry gate can legitimately widen several-fold as it moves out of the money or at 09:35.
  - Outside the window a false reject costs one skipped 5-minute cycle. A false accept fires a spurious exit or trips the breaker.
  - At the bound, the mid is within 25% of either executable side. The review's 0.10/9.00 example (spread 8.90 > 2.275) is rejected.
  - Reusing `max_spread_pct_of_mid × k` was rejected because it would silently couple the marking gate to each strategy's entry tuning.
  - No rules_options.json key is added. These are not strategy knobs, the same reasoning as `_MANAGE_START_ET`.
- **"Two-sided (bid > 0)" interpretation.** With bid = 0 the spread equals the ask and 0.5 × mid = ask/4 < ask. So under this rule a one-sided quote passes ONLY when ask <= $0.10, and every quote with an ask above $0.10 must have bid > 0.
  - This is deliberately not a literal `bid > 0` on every leg. A literal rule would regress one case: after a big move, an iron condor's untested side (far-OTM wings quoted 0.00/0.05 on the less liquid tasty ETFs) would never be marked outside the guard window. tasty's 21-DTE `dte_exit` and its profit target could not fire, and the position's P&L would be invisible to the breaker for weeks.
  - With a sub-dime ask, a one-sided quote moves the mid by at most $0.05 per share ($5 per contract), the same order as `limit_buffer_usd` 0.02 plus one 0.03 escalation step.
  - The operator can make the rule literal later by adding `bid > 0 and` to `_quote_markable`. This interpretation is surfaced in the planning return.
- **WR-07 gate per call site** (inside `_manage_position`, the only consumer of `quotes`):
  - Outside the window (`dte > assignment_guard_dte`), `_quote_markable` gates every leg before all of: `mark_spread` (breaker P&L via the returned unrealized value), `manage_decision` / `manage_decision_debit` (profit_target / stop_loss / dte_exit), and the non-aggressive `close_legs` those decisions trigger.
  - Inside the window, `_quote_ok` gates every leg before the `mark_spread` → decision → `close_legs(aggressive=True)` path. Both decision functions return `"assignment_guard"` first whenever `dte <= cfg.assignment_guard_dte` (strategy.py l.307 and l.352), so the mark cannot change the decision there. In the window `dec` is never None, so the mark is never returned as breaker P&L.
  - `close_legs` inside `open_position`'s entry unwind uses the entry chain quotes, which already passed `leg_is_liquid`. That path is unchanged.

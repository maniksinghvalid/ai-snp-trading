<objective>
Build `backtester/run.py` — the CLI composition root (BT-01/BT-03/BT-04). It parses
`--symbols/--start/--end/--rules-json/--output-dir`, loads the SAME `rules.json` via the SAME
`bot.config.loader.load_strategy_config` the live bot uses (BT-01 "reads the same rules.json"),
validates inputs before any network fetch (V5), enforces the live-DB collision guard (Pitfall
4), constructs `SimulatedBarFeed` + `BacktestHarness`, runs the replay, and hands the captured
trade-log to `backtester.report.write_report` to emit `summary.json` + `trades.csv`.

This plan isolates the two security-relevant concerns of the phase into the one place they
belong — the CLI trust boundary: untrusted operator CLI input (validated) and the scratch-DB
guard that prevents a backtest from ever opening the live paper-trading database.

Scope boundary reminder (06-RESEARCH Open-Q2): the CLI runs the current `partial_be_trail`
exit model only; `fixed_2r`/`full_to_1p5r_trail` are Phase 7 (07-06) territory — surface a
clear message if a rules.json with a non-`partial_be_trail` exit.model is supplied (the loader
already fail-closes on those; do not attempt to run them here).
Output: `backtester/run.py`, `tests/backtester/test_run.py`.
</objective>

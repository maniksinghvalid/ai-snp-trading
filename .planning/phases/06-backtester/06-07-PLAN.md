<objective>
Close the yfinance-window and point-in-time look-ahead defects in `backtester/feed.py` (CR-02,
CR-03, CR-04, CR-07). These are three of the seven confirmed BLOCKER defects that break
multi-day replay: the advertised replay window is a fiction (58 trading days claimed, ~21
actually fetched), `next_bar` silently crosses session boundaries, premarket highs are fetched
relative to "now" instead of the replay day, and the daily-scan `TodayPrice` is built from
full-day look-ahead data.

Purpose: make the feed a trustworthy point-in-time data source so a backtest spanning more than
one trading day (the tool's actual purpose) produces correct, loud-on-failure results — the
foundation Plans 08 and 09 build on.

Output: a corrected `backtester/feed.py` plus feed-level regression tests. No live `bot/` code is
touched (the feed only consumes `bot.scanner.fetcher` kernels).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| yfinance network → feed | Untrusted external market data (NaN rows, gaps, wrong-day frames) crosses into the replay dataset |
| CLI date range → feed | Operator-supplied [start,end] may exceed the available 5m window |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-07-01 | Tampering | yfinance 5m frames (NaN/wrong-day/missing rows) | mitigate | Route every frame through `get_ticker_frame` (Pitfall 3 casing + all-NaN drop); `_enforce_coverage` raises `BacktestWindowError` naming any trading day with zero bars — no silent empty replay |
| T-06-07-02 | Denial of Service | out-of-window date range | mitigate | `_enforce_window` cutoff at 60 calendar days raises loudly before any zero-result replay; coverage guard names missing days |
| T-06-07-03 | Information disclosure | look-ahead leakage into point-in-time values | mitigate | `next_bar` same-session constraint; premarket-only `premarket_highs`/`synthetic_today_price` prevent future-bar data leaking into a decision |
| T-06-07-SC | Tampering | npm/pip/cargo installs | accept | No new package installs — `pandas`, `pandas_market_calendars`, `yfinance` are already project dependencies; nothing to audit |
</threat_model>

<objective>
Close the non-blocking test-suite time bomb 06-VERIFICATION and 06-REVIEW (WR-06) recorded: the
backtester tests hardcode `2026-06-01`/`2026-06-02` fixture dates. `SimulatedBarFeed._enforce_window`
raises `BacktestWindowError` on a cache MISS when `start < now - 60 calendar days`; the test mocks
always miss the cache, so once the wall clock passes ~2026-08-01 the entire `tests/backtester/` suite
goes red on a calendar date with no code change. This is a real, near-term (weeks-out) suite failure,
but explicitly non-blocking relative to the two BLOCKER gaps (closed in 06-10/06-11) — it lands in a
later wave and does not gate them.

Purpose: make the regression suite self-dating so the CR-01/CR-04/CR-05/CR-06/coverage/window proofs
stay green indefinitely, without weakening any assertion.

Output: a `recent_session_days(n)` helper in fixtures.py and a mechanical retrofit of the hardcoded
date anchors across the four backtester test files to use it. Zero production-code changes — this plan
touches ONLY test files.

Note: this plan depends on 06-10 and 06-11 purely for file-edit ordering — both add new test functions
to test_feed.py / test_harness.py, and their new fixtures already use a runtime-derived recent trading
day (they do NOT contribute to this time bomb). This plan retrofits the pre-existing hardcoded
fixtures; it must run AFTER those plans land so it edits their final file state.
</objective>

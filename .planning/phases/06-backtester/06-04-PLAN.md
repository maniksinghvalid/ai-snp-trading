<objective>
Build the backtest performance report (BT-03): `compute_metrics` (win rate, average
R-multiple, max drawdown, profit factor, total trades) and `write_report` (a per-trade CSV +
a `summary.json`). Metrics come from a list of closed-trade dicts using the phase trade-log
contract keys — the SAME list the harness (06-05) captures from `SimulatedExecution` fills and
closed `PositionState`s.

CRITICAL design correction (verified against source, overrides 06-RESEARCH's "reuse
get_closed_trades" note): NOTHING in `bot/` writes the `trades` table (no `INSERT INTO trades`
exists anywhere in `bot/`), so `StateStore.get_closed_trades()` returns an EMPTY list on a
backtest run — it must NOT be the trade-log source. And the `trades` schema has no
`realized_pnl` column (only entry_price/exit_price/quantity/exit_reason/r_multiple/closed_at);
`get_daily_trade_stats` itself computes PnL as `(exit_price - entry_price) * quantity`. So
`compute_metrics` DERIVES realized_pnl the same way — it does not read a stored field.

Purpose: one well-named metrics module (the documented extension point for future parameter
sweeps) with one test file; no scattered pandas one-liners.
Output: `backtester/report.py`, filled `tests/backtester/test_report.py`.
</objective>

<objective>
Close BLOCKER Gap 2 from 06-VERIFICATION: the daily -2R circuit breaker (SignalEngine Gate 7) can
NEVER trip during a backtest because nothing writes the `trades` DB table during a replay —
`backtester/harness.py::_capture_closed_trades` only appends to the in-memory `trade_log` list, so
`store.get_daily_trade_stats` (the `SELECT ... FROM trades WHERE DATE(closed_at)=?` Gate 7 depends
on) always returns `realized_pnl=0.0`. A live risk rule that is part of the SAME reused
StrategyCore/SignalEngine FSM is therefore silently absent from every backtest result, directly
contradicting BT-01's "exact same ... FSM" claim and the harness's own module docstring
(lines 40-43) which asserts Gate 7 "can still block entries".

Also fold in the two non-blocking items 06-VERIFICATION recorded for this area (cheap, same theme):
the wrong-sign exit slippage in `execution.py` (lines 111, 127 add slippage to a SELL exit, inflating
every exit price and overstating performance whenever slippage_usd > 0), and correcting the false
Gate-7 docstring claim.

Purpose: restore true live/backtest FSM parity for the -2R breaker — the backtest must exercise the
SAME entry-blocking behavior a live losing day would — and make exit-fill P&L directionally honest.

Output: a new parameterized `StateStore.record_trade(...)` (mirrors `record_position`); a
`_capture_closed_trades` that persists each captured trade into the SCRATCH store so Gate 7 sees it;
the exit-slippage sign fix; a corrected harness docstring; and two regression tests (Gate-7 trip on an
engineered losing day; exit-slippage direction). The scratch-only DB isolation guaranteed by run.py's
existing live-DB collision guard is preserved (run.py is not modified).
</objective>

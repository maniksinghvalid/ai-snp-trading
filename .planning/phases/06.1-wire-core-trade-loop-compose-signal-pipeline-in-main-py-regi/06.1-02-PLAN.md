<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Broker (OpenD) → gateway | get_positions() is untrusted external truth; a malformed/empty frame must not crash reconcile_once (degrade like startup_reconcile). |
| Gateway → in-memory manager state | reconcile_once mutates `manager._positions` and `store.conn` — a race with manage_exit corrupts FSM state. |
| Gateway → Telegram | drift alert dispatch must be fire-and-forget; a Telegram failure must never break the reconcile loop (ALERT-04). |

## STRIDE Threat Register (logic-integrity, per security_enforcement)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06.1-RECONCILE | Tampering | reconcile_once racing manage_exit on the same position (Pitfall 6) | mitigate | Skip any code in `manager._exiting`; both run on the single asyncio loop so the skip-check + close are atomic between awaits. The `_exiting` set is populated by Plan 03 (manager); reconcile reads it via `getattr(...,"_exiting",set())` so it is safe even before Plan 03 lands. |
| T-06.1-RECONCILE-DDOS | Denial of Service | reconcile_once Telegram spam if a position is perpetually "externally closed" | mitigate | Delete the code from `manager._positions` immediately after alerting so the next 75s cycle finds nothing to re-close; alert fires once per drift event. |
| T-06.1-RECONCILE-CRASH | Denial of Service | malformed/empty broker frame crashing the loop | mitigate | RET_OK guard + len()>0 check before iterating (reuse startup_reconcile shape); reconciliation_loop catches non-CancelledError exceptions and continues. |
| T-06.1-INFO | Information disclosure | exit_order_id / order IDs in audit + alerts | accept | Broker order IDs are not secrets; no credentials cross this path. |
| T-06.1-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this phase (RESEARCH: no new external packages). N/A. |
</threat_model>

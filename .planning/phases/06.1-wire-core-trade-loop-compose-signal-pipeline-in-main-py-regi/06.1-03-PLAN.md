<objective>
Fix the broken exit-fill to alert/state delivery path in `bot/position/manager.py` (WARNING-01 / D-01 / D-02 / EXEC-05 / ALERT-02).

The current bug: `_place_exit_order()` always returns `None`, so `pos.exit_order_id` is never set, so `_find_position_by_exit_order_id()` never matches an exit fill, so `_on_exit_fill()` never fires, so 4 of 5 exit-reason alerts (breakeven/trail/stop-out/force-close) never reach the alerter live and `remaining_quantity` never decrements via fills.

The fix (D-01/D-02): `manage_exit()` already returns an `int` total filled-qty (engine.py line 448: `return total_filled`) and places N cancel-replace orders internally — there is no single exit order_id. Make `_place_exit_order()` return that int; have both call sites apply the exit (decrement `remaining_quantity`, mark CLOSED at 0) and fire `on_exit_alert(code, reason, r)` synchronously from the return value. Add a `_exiting` set so the SAFE-03 reconcile loop (Plan 02) can skip in-flight exits (Pitfall 6).

Purpose: closes WARNING-01 and makes ALERT-02/EXEC-05 reachable live. This seam is independent of gateway.py and bot.py (different file), so it runs in parallel with Plan 02 in Wave 1.
Output: a PositionManager whose exits decrement state and fire alerts deterministically from the manage_exit return value.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ExecutionEngine (manage_exit) -> PositionManager | The int return is the only trusted exit-qty source; a wrong value corrupts remaining_quantity / CLOSED state. |
| PositionManager -> Telegram alerter | Exit alert must be best-effort; an alerter failure must never break the FSM transition (ALERT-04). |
| PositionManager._exiting -> gateway.reconcile_once | The in-flight set is the cross-component guard preventing reconcile from double-acting on a position mid-exit. |

## STRIDE Threat Register (logic-integrity, per security_enforcement)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06.1-EXIT-QTY | Tampering | exit-fill delivery firing alerts/state on the wrong qty | mitigate | Drive remaining_quantity decrement and CLOSED transition strictly from the manage_exit int return (max(0, remaining - filled_qty)); never infer from quantity-matching a broker fill (EXEC-05). int(filled_qty) and the 0-on-exception path bound the value. |
| T-06.1-EXIT-RACE | Tampering | reconcile_once acting on a position mid-manage_exit | mitigate | self._exiting.add(code) before manage_exit, discard in finally; gateway.reconcile_once skips codes in _exiting (Pitfall 6). The finally guarantees the code is removed even if manage_exit raises. |
| T-06.1-EXIT-ALERT-DUP | Spoofing | duplicate/false exit alert (partial double-firing) | mitigate | Keep the single existing partial alert block; do NOT add a second alert at the partial call site. Stop-out alert fires once per filled exit. |
| T-06.1-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this phase (RESEARCH: no new external packages). N/A. |

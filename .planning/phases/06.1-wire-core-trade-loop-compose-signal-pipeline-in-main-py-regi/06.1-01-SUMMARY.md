# Phase 06.1 Plan 01: Wave-0 RED Test Infrastructure Summary

**One-liner:** Wave-0 TDD RED phase — 9 failing integration/unit tests locking the acceptance contract for all 6 composition seams before wiring lands in Waves 1–3.

## What Was Built

### Task 1: tests/service/test_trade_loop_integration.py (NEW FILE)

Created a new integration test file with 6 named test functions covering every BLOCKER/WARNING identified in the v1.0 milestone audit:

| Test Name | Requirement | Failure Mode Today |
|-----------|-------------|-------------------|
| `test_push_handler_registered` | BLOCKER-01 / SIG-01 | TypeError: `signal_engine` kwarg not accepted |
| `test_bar_push_fires_on_bar_closed` | SIG-01 | TypeError: `signal_engine` kwarg not accepted |
| `test_entries_disabled_blocks_entry` | BLOCKER-02 / D-06 | TypeError: `signal_engine` kwarg not accepted |
| `test_entries_enabled_allows_entry` | BLOCKER-02 / D-06 | TypeError: `signal_engine` kwarg not accepted |
| `test_reconcile_task_started` | BLOCKER-03 / SAFE-03 | TypeError: `signal_engine` kwarg not accepted |
| `test_bar_buffer_late_bound` | WARNING-02 / POS-03 | TypeError: `signal_engine` kwarg not accepted |

All 6 tests fail with `TypeError: TradingBot.__init__() got an unexpected keyword argument 'signal_engine'` — the intended RED condition proving `TradingBot` has not yet been extended with the two new constructor parameters.

The `_make_minimal_bot()` helper intentionally passes `signal_engine=` and `risk_engine=` to `TradingBot(...)`. This propagates a clear TypeError immediately at the bot construction call, giving each test an unambiguous failure that turns Green only when Plan 06.1-04 adds those params.

### Task 2: Three failing tests in existing test files

#### tests/position/test_manager.py — `test_exit_alert_fires_after_manage_exit`

Tests the D-01/D-02 contract: when `engine.manage_exit()` returns `filled_qty=10` after a stop-out, the `on_exit_alert` callback must fire. RED today because `_place_exit_order()` returns `None` (fire-and-forget path — confirmed in `manager.py` line 843). The stop-out block sets `pos.exit_order_id = None` and never calls `on_exit_alert`.

**Failure:** `AssertionError: on_exit_alert must be called once after stop-out fill; calls=[]`

#### tests/gateway/test_gateway.py — `test_set_handler_delegates_to_quote_ctx`

Tests that `gw.set_handler(handler)` delegates to `gw._quote_ctx.set_handler(handler)`. RED today because `MoomooGateway` has no `set_handler` method at all.

**Failure:** `AttributeError: 'MoomooGateway' object has no attribute 'set_handler'`

#### tests/gateway/test_gateway.py — `test_reconcile_once_externally_closed`

Tests that `reconcile_once(store=..., manager=..., alerter=...)` detects an externally-closed position, updates the DB, removes from `_positions`, and returns the code in `result["closed"]`. RED today because `reconcile_once()` is a no-op stub with signature `(self)` — no kwargs accepted.

**Failure:** `TypeError: MoomooGateway.reconcile_once() got an unexpected keyword argument 'store'`

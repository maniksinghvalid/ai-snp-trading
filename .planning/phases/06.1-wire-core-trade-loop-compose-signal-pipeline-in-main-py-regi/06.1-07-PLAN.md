<objective>
Close the reconcile half of CR-01 (no steady-state recovery for a CLOSED-but-held / drifted
position) and CR-03 (a mid-session orphan is adopted into the DB and 5m feed but never
registered in `manager._positions`, so it is never managed until restart). Add the
steady-state recovery branch to `reconcile_once` that `startup_reconcile` already has, and a
`manager.adopt_orphan(...)` helper that co-locates the in-memory registration with the
manager's invariants. Harden `tests/gateway/test_gateway.py` (and a manager unit test for
`adopt_orphan`) to drive the in-memory effects — the existing reconcile tests only assert
return-dict shape, never that a position becomes managed.

Purpose: This is the SAFE-03 milestone CORE VALUE — the reconciliation loop must make broker
truth win in steady state, not only at boot. A position adopted-without-protect or a
CLOSED-but-held broker position is unmanaged live exposure (the safety analog of fund loss).

Output: A `reconcile_once` with a CLOSED-but-held / qty-drift recovery branch and an
orphan branch that registers the position in-memory via `manager.adopt_orphan`, with the
DRIFT alert task retained and a rowcount-checked audit (no false "adopted").
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| broker → bot (reconcile_once) | The steady-state loop is the last line of defense: it must make broker truth win in-memory, not only at boot. A CLOSED-but-held or unregistered orphan is unmanaged live exposure. |
| gateway (DB + feed) → manager (_positions) | An adopted position must cross into manager._positions or on_bar never manages it. |
| reconcile_once → audit log | A drift_orphan_adopted audit must reflect a real adoption, never a no-op INSERT, or the operator is falsely reassured. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06.1-07-01 | Denial of protection | reconcile_once lacks CLOSED-but-held / qty-drift branch (steady state) | mitigate | Add recovery branch mirroring startup_reconcile; re-arm in-memory phase + sync remaining to broker qty so on_bar resumes; alert. Test proves re-arm. |
| T-06.1-07-02 | Denial of protection | orphan adopted to DB+feed but not manager._positions | mitigate | reconcile_once calls manager.adopt_orphan → on_bar manages it same cycle. Test proves _positions registration + on_bar reachability. |
| T-06.1-07-03 | Repudiation / audit integrity | INSERT OR IGNORE no-op audited as drift_orphan_adopted (WR-04) | mitigate | rowcount-gated audit; no-op logs reconcile_orphan_insert_noop, emits no adopted audit. |
| T-06.1-07-04 | Denial (alert loss) | fire-and-forget DRIFT alert GC'd before send (WR-03) | mitigate | Retain task in self._bg_tasks with add_done_callback discard. |
| T-06.1-07-05 | Tampering (race) | recovery branch races an in-flight manage_exit | accept (guarded) | Existing _exiting skip (804-806) is preserved so the recovery/orphan branches never act on a mid-exit code. |

No high-severity threat is left unmitigated: the steady-state recovery gap and
adopt-without-protect are both closed with tests that would have caught them.
</threat_model>

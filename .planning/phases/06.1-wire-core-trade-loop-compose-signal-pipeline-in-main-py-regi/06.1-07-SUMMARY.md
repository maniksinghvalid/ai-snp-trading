**One-liner:** Closed CR-01 reconcile half (CLOSED-but-held/qty-drift steady-state recovery) and CR-03 (orphan adopt-and-protect) by adding `manager.adopt_orphan()` and a recovery branch to `reconcile_once`, with DRIFT alert task retention (WR-03) and rowcount-gated audit (WR-04).

## What Was Built

### Task 1: manager.adopt_orphan() — CR-03 in-memory registration (TDD)

**Problem:** `reconcile_once`'s orphan branch wrote a DB row + subscribed the 5m feed but never registered a `PositionState` in `manager._positions`. The adopted position was invisible to `on_bar` until the next restart.

**Fix (`bot/position/manager.py`):**

Added `adopt_orphan(self, code, qty, avg_cost, stop, position_id=None) -> PositionState`:
- Builds a `PositionState` with `phase=ACTIVE`, `entry_price=avg_cost`, `initial_stop=stop`, `trail_stop=stop`, `full_quantity/remaining_quantity=qty`, `entry_order_id=""`, `avg_fill_price=avg_cost`, `opened_at/updated_at=now_et()`.
- DB-first write via `_persist_position(event="orphan_adopted")` — Pitfall G honoured.
- Registers `pos` in `self._positions[code]` so `on_bar` manages it the same cycle.
- Logs `orphan_adopted_in_memory` with `code/qty/stop/position_id`.
- Returns the `PositionState`.
- Does NOT subscribe — the gateway owns feed subscription.

**Verification:**
- `grep -nc 'def adopt_orphan' bot/position/manager.py` == 1 ✓
- `TestAdoptOrphan::test_adopt_orphan_registers_in_positions`: `manager._positions["US.AAPL"]` has phase=ACTIVE, remaining_quantity=200, full_quantity=200, entry_price=150.0, initial_stop=148.5, trail_stop=148.5 ✓
- `TestAdoptOrphan::test_adopt_orphan_position_is_managed_by_on_bar`: after adopt, `on_bar(close=147.0 < trail_stop=148.5)` triggers STOP_OUT path (position CLOSED) ✓

### Task 2: reconcile_once CR-01 / CR-03 / WR-03 / WR-04 fixes (TDD)

**Problem:** `reconcile_once` (a) had no recovery branch for CLOSED-but-held / qty-drift in steady state (CR-01), (b) orphan branch never called `adopt_orphan` (CR-03), (c) DRIFT alert was a bare `asyncio.create_task` (WR-03), (d) INSERT OR IGNORE no-op emitted false `drift_orphan_adopted` audit (WR-04).

**Fix (`bot/gateway/gateway.py`):**

(a) `__init__`: Added `self._bg_tasks: set = set()` for retained alert tasks (WR-03).

(b) In `reconcile_once` in-memory vs broker loop — added ELSE branch for `code in broker_map`:
- Detects `phase==CLOSED` while broker holds shares (`is_closed_but_held`) OR `remaining_quantity != broker_qty` (`is_qty_drift`).
- Re-arms: if `phase==CLOSED`, sets `pos.phase = PositionPhase.ACTIVE`; syncs `pos.remaining_quantity = broker_qty`.
- `UPDATE positions SET remaining_quantity=?, phase=?, updated_at=?` DB update.
- Audits `reconcile_qty_drift` with code/stored_qty/broker_qty.
- Fires DRIFT alert via `_retain_task()` (WR-03).

(c) Orphan branch — after `INSERT OR IGNORE`, checks `cursor.rowcount`:
- `rowcount == 0` (no-op collision): logs `reconcile_orphan_insert_noop`, skips audit and adopt.
- `rowcount == 1` (new row): audits `drift_orphan_adopted`, calls `manager.adopt_orphan(code, qty, avg_cost, stop, position_id)`, then subscribes.

(d) `_retain_task(coro)` helper: `t = asyncio.create_task(coro); self._bg_tasks.add(t); t.add_done_callback(self._bg_tasks.discard)`. All DRIFT alerts (externally-closed and CLOSED-but-held paths) use this helper.

<decrement_ownership_decision>
## Decrement-ownership convention (RESOLVES CR-02) — read before editing

The bug is an asymmetry between the two FSM exit actions:

- STOP_OUT branches in `evaluate_close` (state.py ~208/222/233) RETURN `remaining_quantity`
  but do NOT mutate it; the handler `_trigger_stop_out` applies the single decrement on fill
  (manager.py ~692). This path is CORRECT.
- The PARTIAL branch in `evaluate_close` (state.py:214) DOES mutate
  `remaining_quantity -= partial_qty`; the handler `_trigger_partial_profit` then decrements
  AGAIN on a real fill (manager.py:601). This double-counts.

**Decision: HANDLER OWNS THE DECREMENT (uniform).** `evaluate_close` becomes purely
advisory on quantity — it computes and RETURNS `partial_qty` but must NOT mutate
`remaining_quantity`. The handler applies exactly one decrement, driven by the broker's
`filled_qty`. This makes PARTIAL symmetric with STOP_OUT (which already works this way) and
makes `evaluate_close` side-effect-free on quantity. Both tasks below must respect this
single convention; do NOT introduce a second decrement anywhere.
</decrement_ownership_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bot → broker (manage_exit) | The bot's in-memory `remaining_quantity` and `phase` must stay reconciled with the broker's actual position after each exit attempt. A divergence is unmanaged live exposure (the safety analog of fund loss). |
| FSM (evaluate_close) → handler (manage_exit fill) | Quantity-decrement ownership crosses this boundary; a disagreement double-counts or under-counts shares. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06.1-06-01 | Tampering (state corruption) | _trigger_partial_profit double-decrement | mitigate | Single-owner decrement (handler), driven by broker filled_qty; test asserts remaining == broker truth (300/99→201). |
| T-06.1-06-02 | Denial of protection | _trigger_stop_out zero/short fill leaves CLOSED-but-held | mitigate | Revert to managed phase when remaining > 0, persist DB-first, log stop_out_incomplete; test proves on_bar retries. |
| T-06.1-06-03 | Information disclosure / silent loss | short fill discarded (WR-02), partial fill count lost | mitigate | Credit actual filled_qty on short fills; log partial_short_fill / stop_out_incomplete so the operator sees divergence. |
| T-06.1-06-04 | Repudiation / audit integrity | A failed exit persisted as success would falsify the audit trail | mitigate | stop_out_incomplete is a distinct persist event; success events (stop_out_filled) fire ONLY on full close — no false "closed" audit. |

No high-severity threat is left unmitigated: the fail-open stop-loss and quantity corruption
are both closed in this plan with tests that would have caught them.
</threat_model>

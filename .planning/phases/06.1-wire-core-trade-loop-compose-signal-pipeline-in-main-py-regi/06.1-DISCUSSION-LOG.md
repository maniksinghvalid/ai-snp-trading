## Exit-fill → alert path (WARNING-01 / ALERT-02 / EXEC-05)

| Option | Description | Selected |
|--------|-------------|----------|
| Synchronous from return | After manage_exit() returns filled-qty, PositionManager applies exit + fires alert directly; retire exit_order_id push-match path for exits | ✓ |
| Feed FillEvents back | manage_exit emits FillEvent/callback per order_id; existing _on_exit_fill path runs unchanged; needs engine refactor (N order_ids) | |
| Single tracked exit order | One order_id per exit on pos.exit_order_id, reuse push path; conflicts with retry-until-flat cancel-replace | |

**User's choice:** Synchronous from return value.
**Notes:** Scout finding drove this — `engine.manage_exit()` returns a filled-qty `int` (not an order_id) and places multiple cancel-replace orders internally, so the audit's literal "set exit_order_id" doesn't fit the code. All exits are bot-initiated (D-01 synthetic stop; no resting broker stops on SIMULATE), and SIMULATE push is unreliable — so the synchronous return value is the authoritative, minimal fix.

## _entries_enabled gate (SVC-02 / D-09)

| Option | Description | Selected |
|--------|-------------|----------|
| Gate the entry branch | Always process_bar (management); run signal→risk→exec only when _entries_enabled; entry-only, no spurious intent/tally | ✓ |
| Gate at consume_intent only | Run signal+risk every bar, block only final consume_intent; persists intents + advances tally during pause | |
| Gate inside SignalEngine | Pass flag into SignalEngine so it won't emit; couples pure engine to live service state | |

**User's choice:** Gate the entry branch in _on_bar_closed.
**Notes:** Position-management must run every closed bar even when entries are paused (trail/partial/stop). Gating the entry branch is entry-only by construction and avoids polluting the daily intent tally during a disconnect-pause.

## reconcile_once() drift logic (SAFE-03)

| Option | Description | Selected |
|--------|-------------|----------|
| Broker-truth-wins + alert | Reuse startup_reconcile core; externally-closed (no in-flight exit) → mark closed + stop managing + alert; orphan → adopt-and-protect; skip in-flight exits | ✓ |
| Detect + alert only | Diff and report drift, no in-memory mutation; leaves correction to restart; surfaces but doesn't fix the bug | |
| Full override each cycle | Re-run full startup_reconcile every 75s; heaviest, risks clobbering in-flight FSM transitions | |

**User's choice:** Broker-truth-wins + alert.
**Notes:** The specific audit bug is a manual broker-UI close going undetected until restart; this option actually fixes it. Safety nuance: skip positions with an active manage_exit to avoid racing live transitions. Reuses proven startup_reconcile broker-truth logic.

<objective>
Compose the core trade loop inside `TradingBot` (`bot/service/bot.py`) — the central wiring that closes BLOCKER-01 (pipeline not composed), BLOCKER-02 (_entries_enabled write-only), and the run()-side of BLOCKER-03/POS-03.

This must land in `TradingBot`, not `main.py`, because BarAggregator needs the running asyncio loop and PositionManager needs BarAggregator._bar_buffer — and main.py builds everything before `asyncio.run()` (D-03). Changes: (1) add `signal_engine` and `risk_engine` constructor params (injected by main.py in Plan 05); (2) add the async `_on_bar_closed(bar_data)` orchestrator with the D-06 entries gate; (3) in `run()` after the readiness gate, construct `BarAggregator(get_running_loop(), self._on_bar_closed)`, call `gateway.set_handler(...)` (from Plan 02), late-bind `bar_buffer` into PositionManager (POS-03), and start `gateway.reconciliation_loop(store, manager, alerter)` (from Plan 02) as a task (D-08); (4) cancel that task in `finally` (mirror the watchdog); (5) call `bar_agg.reset_session()` only at market open in the subscribe job.

Purpose: this is the keystone seam that makes the leaf components into a functioning loop. Depends on Plan 02 (`set_handler`, `reconciliation_loop` signature) and Plan 03 (`_exiting` set is read by the reconcile task it starts).
Output: a TradingBot.run() that, once OpenD delivers 5m pushes, runs the full scan->bar->signal->size->order->manage->alert loop with a steady-state reconcile.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SDK push thread -> asyncio loop | BarAggregator bridges via run_coroutine_threadsafe into _on_bar_closed; a malformed bar_data dict crossing here must not crash the loop. |
| Watchdog (_entries_enabled write) -> _on_bar_closed (read) | The entry-pause control: an entry firing while entries are paused = an unwanted order submission (the SVC-02/D-06 control). |
| TradingBot -> reconcile task | The reconcile task mutates manager state on the same loop; it must be cancellable on shutdown to avoid acting during teardown. |

## STRIDE Threat Register (logic-integrity, per security_enforcement)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06.1-ENTRY-GATE | Elevation of Privilege | _on_bar_closed entry branch bypassing _entries_enabled | mitigate | The `if not self._entries_enabled: return` gate sits AFTER position_manager.on_bar and BEFORE signal_engine.on_bar, so no entry path (signal/risk/consume_intent) is reachable while paused. Wave-0 tests test_entries_disabled_blocks_entry / test_entries_enabled_allows_entry assert both directions. The flag is read here for the first time, making the watchdog's disconnect-pause (D-09) enforceable. |
| T-06.1-MALFORMED-BAR | Spoofing / Denial of Service | malformed K_5M push cascading into a loop crash | mitigate | BarEvent construction in _on_bar_closed is wrapped in try/except (log on_bar_closed_bar_construction_error + return); BarAggregator._handle_row already validates rows upstream (T-03-01). |
| T-06.1-RECONCILE-LEAK | Denial of Service | reconcile task surviving shutdown and acting during teardown | mitigate | self._reconcile_task initialised to None at run() top; finally cancels it with await + CancelledError swallow, mirroring the proven watchdog-cancel pattern. |
| T-06.1-RESET-DEDUP | Tampering | reset_session on reconnect wiping _seen_time_keys -> replayed/repainted bars | mitigate | reset_session is called ONLY in _job_market_open_subscribe (genuine session start), never on reconnect; set_handler stays registered from run() startup (Pattern 4). |
| T-06.1-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this phase (RESEARCH: no new external packages). N/A. |
</threat_model>

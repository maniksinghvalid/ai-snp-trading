# Phase 06.1 Plan 06: CR-02 and CR-01 Handler Half Gap-Closure Summary

**One-liner:** Fixed double-decrement quantity corruption (CR-02) and fail-open stop-loss (CR-01) by enforcing handler-owns-decrement convention and re-protecting positions on zero/short fills.

## What Was Built

### Task 1: Make evaluate_close advisory-only on quantity (CR-02 / WR-01)

**Problem:** `evaluate_close` decremented `remaining_quantity` in the PARTIAL branch (state.py:214), then `_trigger_partial_profit` decremented again on a real fill (manager.py:601). A 300-share position scaling out 99 ended at 102, not 201 (broker truth).

**Fix:**
- `bot/position/state.py`: Removed `self.remaining_quantity -= partial_qty` from the ACTIVE PARTIAL branch. `evaluate_close` now returns `partial_qty` without mutating `remaining_quantity`. Added docstring documenting the handler-owns-decrement convention.
- `bot/position/manager.py`: `_trigger_partial_profit` now owns the single decrement driven by broker `filled_qty`. Added `partial_short_fill` warning log on short fills. Added `pos.phase = PositionPhase.CLOSED` when decrement drives `remaining_quantity` to 0 (WR-01).

**Verification:** `grep -nc 'remaining_quantity -=' bot/position/state.py` returns 0.

### Task 2: Re-protect on zero/short stop-out fill (CR-01 / SAFE-03 / WR-02)

**Problem:** `_trigger_stop_out` was guarded by `if filled_qty > 0` with no else branch. On a zero fill, the position was left `CLOSED` in memory (evaluate_close set it before the handler ran) with `remaining_quantity > 0`. `on_bar` early-returns on CLOSED so the stop was never retried.

**Fix:**
- `bot/position/manager.py`: `_trigger_stop_out` restructured as not-fail-open:
  - **Full fill** (`filled_qty >= qty`): keep existing CLOSED + `stop_out_filled` + alert behavior.
  - **Zero or short fill** (`filled_qty < qty`): credit actual filled shares (WR-02), revert `pos.phase = prev_phase` so `on_bar` retries next bar, persist `stop_out_incomplete`, log `stop_out_incomplete` at error level. Success alert does NOT fire.
  - Defensive fallback: if `prev_phase` is None or CLOSED, reverts to ACTIVE.

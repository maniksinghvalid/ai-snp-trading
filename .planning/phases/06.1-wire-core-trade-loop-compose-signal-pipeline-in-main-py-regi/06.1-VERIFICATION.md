### Summary

**Six thread-safety findings from 06.1-08-REVIEW — all CLOSED:**

**CR-01 (every DB writer/reader guarded) — CLOSED:**
Fourteen new StateStore methods, each acquiring `with self._lock:` around a short synchronous
block (conn.execute + commit + row_factory flip/reset). All 13 former raw-conn call sites in
gateway.py, manager.py, risk_engine.py, execution/engine.py, signal_engine.py, and scanner.py
are migrated. Acceptance grep returns empty: zero raw-conn `.execute/.commit/.row_factory`
outside store.py.

**CR-02 (lock never held across await) — CLOSED:**
store.py has zero `await` tokens. The reconcile broker I/O (`await self._derive_lod_for_orphan`,
`await self.subscribe`) in gateway.py sits between guarded store-method calls, never inside one.

**WR-01 (regression test drives the real race) — CLOSED:**
`TestStressRowFactoryRace` (test_store_concurrency.py) uses `sys.setswitchinterval(1e-6)` and
8 `threading.Thread` workers x 1500 iterations of all three row_factory-flipping read methods.
Mutation proof: removing the RLock produces 3,642 corruption events; the correct tree produces 0.

**WR-02 (raw conn deprecated; outer locks removed) — CLOSED:**
`conn` property docstring contains "DEPRECATED — internal/read-debug only". The four
`with self._store.lock():` wrappers in bot.py executor jobs are removed (`grep -c` == 0).

**WR-03 (busy_timeout) — CLOSED:**
`PRAGMA busy_timeout=5000` at store.py:231, immediately after `sqlite3.connect`.

**IN-01 (comment states enforced invariant) — CLOSED:**
`conn` property docstring and open() comment rewritten to state the invariant that all DB access
routes through guarded methods and the lock is never held across an await.

**No regression in prior 7 truth-groups:** All trade-loop safety fixes from plans 06.1-06/07
(CR-01 stop-loss reprotect, CR-02 double-decrement, CR-03 orphan adoption) are intact. The
433-test suite (vs 428 before gap-closure, vs 432 after plan 06.1-09 Tasks 1-3, vs 433 after
WR-01 hardening commit `862be63`) is green.

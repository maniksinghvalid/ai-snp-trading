    dotted path into the parsed `rules_options.json` dict, and set the leaf via `json.loads(value)`

    does not already exist in the file — a typo must fail loudly, never silently add a key the
    schema ignores. Never mutate `rules_options.json` on disk (D-15).

    `main(argv=None) -> int`, in this order (mirroring `backtester/run.py`'s V5 discipline):
    1. Validate dates, symbols and every numeric flag BEFORE any config load, filesystem write or
       network call; on failure `print(f"[ERROR] {exc}", file=sys.stderr); return 1`.
    2. Create the run directory; read `--rules` as JSON, `apply_overrides`, write the result to
       `<out>/config.json`, then `load_options_config("<out>/config.json")`. This single move
       satisfies D-15 (effective config recorded per run) AND D-16 (config.json artifact) AND runs
       every override through the real jsonschema validation — an out-of-range override fails here,
       not silently mid-run. Catch `ConfigError` → `[ERROR]` → `return 1`.
    3. `MassiveDataSource(load_massive_api_key())`; catch `MassiveApiError` → `[ERROR]` → `return 1`.
    4. Compute the warm-up start: `--iv-warmup-days` NYSE days before `--start`, via
       `backtester.options.data.trading_days`. Build one `OptionChainSource` per symbol (strip the
       `US.` prefix for the Massive root, keep the `US.` code as the engine's key) over
       [warmup_start, end] and `load(cfg.min_dte, cfg.max_dte, cfg.prefer_monthly, strike_band_pct)`.
    5. Construct `OptionsBacktestEngine(cfg, chains, r=..., slippage_usd=..., commission_per_leg=...,
       spread_pct=..., oi_source=...)`, run it over `trading_days(start, end)` (decision days only —
       the warm-up days feed the IV series, never an entry).
    6. `write_options_report(engine.trade_log, out_dir, starting_capital=cfg.sizing_equity_usd,
       start=..., end=..., extra_assumptions={... every flag above, plus the rules path and the
       label ...})`; print the metrics JSON; `return 0`.
    Module docstring states the same broker-free invariant `backtester/run.py` states, and notes
    that this module constructs no `StateStore` at all (the options backtester keeps its state in
    memory — there is no live options DB to collide with).

    Tests in `tests/backtester/options/test_options_run.py`, all offline (monkeypatch
    `backtester.options_run.load_massive_api_key`, `MassiveDataSource` and `OptionChainSource`):

    closed trade → exit 0, `trades.csv`/`summary.json`/`config.json` all present in `--out`).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI args → run directory + cache paths | `--symbols`, `--out` and `--set` are operator-controlled and reach the filesystem and the config loader |
| local process → api.massive.com | the only network destination in the phase; `MASSIVE_API_KEY` crosses it |
| backtester → live strategy config | `rules_options.json` is the live bot's source of truth and this plan may edit it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-I1 | Information disclosure | `load_massive_api_key` + `_get_json` | mitigate | Key resolved from env/.env, sent only as a Bearer header by the existing client, never printed and never written into `config.json`/`summary.json` (the assumptions block records flags, not credentials). |
| T-09-T1 | Tampering (path traversal) | `--symbols`, `--out` | mitigate | Symbols reach cache filenames only through Plan 09-01's `_SYMBOL_RE`/`_OPTION_TICKER_RE` guards; `--out` is operator-owned and created with `os.makedirs`, no interpolation of untrusted content into it. |
| T-09-T2 | Tampering (config drift) | `--set` overrides | mitigate | Overrides are applied to an in-memory copy and written to the run dir; `rules_options.json` on disk is never rewritten by a run (`git diff --exit-code rules_options.json` is an acceptance criterion), and every override is revalidated by the real jsonschema through `load_options_config`. |
| T-09-E1 | Elevation of privilege | `backtester/options_run.py` | mitigate | Composition root constructs a data source, an engine and a report writer — no gateway, no `StateStore`, no order path. Grep-enforced in the acceptance criteria, mirroring `backtester/run.py`'s invariant. |
| T-09-R1 | Repudiation | result provenance | mitigate | Each run dir carries the effective `config.json`; the results doc cites run-ids and commit hashes; the hypotheses-before-results ordering is asserted from git history before any run starts. |
| T-09-D1 | Denial of service | cold backfill | mitigate | Read-through cache plus 429 backoff; the task carries an explicit wall-clock stop-and-report budget instead of grinding indefinitely. |
| T-09-SC | Tampering (supply chain) | dependencies | accept | Zero new packages installed in this phase. |

**Finding: no high-severity threats.** The one change with live blast radius is the conditional
`rules_options.json` edit; it is bounded to a single pre-registered key, gated on a SUPPORTED
verdict, covered by the existing `tests/options/` suite, and surfaced at the end-of-phase human
verification.
</threat_model>

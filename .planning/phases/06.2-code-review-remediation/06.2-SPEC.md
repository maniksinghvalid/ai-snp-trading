# Phase 06.2 — Code-Review Remediation (Design Spec)

**Date:** 2026-07-02
**Source:** Multi-agent code review of `develop` vs `main` (2026-07-02), 16 confirmed findings, all verified against HEAD (`ec826eb`). None fixed at spec time.
**Approved:** User approved tiered design 2026-07-02.

## Goal

Close all 16 confirmed review findings so the bot is:
- **safe for an unattended live paper run** after Tier 1,
- **behaviorally correct** (gates, reporting, alerts, config-driven stops) after Tier 2,
- **maintainable** (no duplicated reconcile logic, no wasteful re-downloads) after Tier 3.

Each fix lands TDD-style: failing regression test first, then the fix, one atomic commit per finding. Full suite (~480 tests) must pass after every tier. A live premarket UAT gates Tier 1 sign-off.

## Key mechanic (grounds Tier 1.1)

The plumbing already exists — no new machinery needed:
- `ExecutionEngine.consume_intent(intent)` **returns** `Optional[FillEvent]` (`bot/execution/engine.py:104`); `bot/service/bot.py:276` currently discards it.
- `PositionManager.on_fill` → `_on_entry_fill` (`bot/position/manager.py:436`) matches by `entry_order_id`, then handles: `apply_entry_fill`, DB-first persist, daily filled count, pending-intent resolution, and the entry alert callback.
- Therefore the fix is: register an `AWAITING_FILL` `PositionState` (with `entry_order_id = fill.order_id`) via `register_position()` (`manager.py:1003`), then call `on_fill(fill)`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] MagicMock(spec=OrderIntent) hides dataclass instance fields**

- **Found during:** Task 1 GREEN (pre-existing test test_entries_enabled_allows_entry)
- **Issue:** MagicMock(spec=OrderIntent) creates a mock from the class-level attributes of OrderIntent (a dataclass). Dataclass instance fields like intent_id are defined in __init__, not as class attributes, so mock.intent_id raised AttributeError when the new note_intent_resolved() call accessed it.
- **Fix:** Changed MagicMock(spec=OrderIntent) to MagicMock() and added order_intent.intent_id = "test-intent-integration" explicitly in tests/service/test_trade_loop_integration.py.
- **Files modified:** tests/service/test_trade_loop_integration.py
- **Commit:** Included in 3e28b11

**2. [Rule 2 - Missing critical functionality] note_intent_resolved() missing on both resolution paths**

- **Found during:** Task 1 (Finding 1.1) — plan identified _pending_count decrement on both fill AND abandon paths as a requirement
- **Issue:** Plan's behavior spec required note_intent_resolved() on every intent resolution (both fill path and abandon/no-fill path), but original code had no call on either path.
- **Fix:** Added self._signal_engine.note_intent_resolved() after the if/else block in _process_bar so it always fires regardless of fill outcome.
- **Files modified:** bot/service/bot.py
- **Commit:** 3e28b11

## Finding Details

### Finding 1.1 — Fill event discarded (bot.py)

**Was:** await self._execution_engine.consume_intent(intent) returned a FillEvent that was discarded. PositionManager never received the fill.

**Is now:** Return value captured. If fill is not None: construct PositionState(phase=AWAITING_FILL) and call register_position(pos) then on_fill(fill). If fill is None (abandoned): call resolve_pending_intent(intent.intent_id, "ABANDONED"). In both cases, signal_engine.note_intent_resolved() is called so _pending_count stays accurate.

### Finding 1.2 — reconcile_once mass-close on failed broker query (gateway.py)

**Was:** get_positions() failure => ret_pos != RET_OK => broker_data = None => broker_map = {} => every tracked position marked "externally closed". Bot would flat all positions on any transient API failure.

**Is now:** Early return guard after get_positions(). If ret_pos != RET_OK or broker_data is None: log reconcile_skipped_broker_query_failed, send Telegram warning, return {} (skip cycle). Never derive "externally closed" from a failed query.

### Finding 1.3 — Bar handler lost on OpenD reconnect (watchdog.py)

**Was:** _on_reconnect called startup_reconcile + subscribe then set _entries_enabled = True. The new quote context from OpenD restart had no BarAggregator push handler registered, so 5m bars were silently dropped until next manual restart.

**Is now:** After subscribe, before re-enabling entries: if bot._bar_agg is not None, call gateway.set_handler(bot._bar_agg) and log bar_handler_reregistered_after_reconnect. Failure is logged as warning and does not block entry re-enable.

### Finding 1.4 — Cancel-replace uses pre-cancel dealt_qty (engine.py)

**Was:** order_filled_this_round was read from the initial order status check. Cancel was issued. The replacement order used remaining = qty - total_filled computed from the pre-cancel snapshot. Any fill arriving during cancel was missed, causing the replacement order to be over-sized (potential short position from a long exit).

**Is now:** Cancel always first. Then get_order_status(order_id) re-queried to get post_cancel_filled. total_filled += post_cancel_filled (not pre-cancel value). remaining = qty - total_filled. If remaining <= 0, break without placing replacement.

### Finding 1.5 — force_close hardcoded to 15:51 ET every day (bot.py)

**Was:** force_close job used CronTrigger(hour=15, minute=51) — fires every trading day at 15:51 ET. On half-days (e.g. July 3, Dec 24 early close at 13:00 ET), the bot holds positions ~3 hours past market close.

**Is now:** force_close job registered with DateTrigger(run_date=datetime(2099, 1, 1)) as a far-future placeholder. After _job_premarket_scan completes each day, it calls get_force_close_time_et(today) to get the calendar-aware close time, constructs a timezone-aware datetime, then calls reschedule_job("force_close", trigger=DateTrigger(run_date=run_at)). Emits force_close_job_rescheduled log event.

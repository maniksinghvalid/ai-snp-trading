# Phase 06.2 Plan 03: Tier-3 Hygiene Findings (3.1-3.2) Summary

Extracted a single shared `_reconcile_core` so `reconcile_once` and `startup_reconcile` can no longer drift apart on the orphan-adoption ownership guard, and added a caller-owned trading-day-keyed daily-bar cache so the intraday rescan stops re-downloading the full ~500-symbol S&P universe every ~30 minutes.

- `reconcile_once` and `startup_reconcile` (`bot/gateway/gateway.py`) delegate to one shared `_reconcile_core` — the ~200-line near-duplicate close/adopt/protect body is gone; the SAFE-OG-01 / Finding 2.5 ownership + duplicate-code orphan guard is now a single guard set that cannot drift between the two entry points

## Decisions Made

- **3.1:** `_reconcile_core` discriminates the two call sites via `alerter is None` (`is_startup`) rather than an explicit boolean parameter — this matches the two production call shapes exactly (`reconcile_once` always has a real `alerter`; `startup_reconcile` always passes `alerter=None`, since Telegram alerts don't make sense before the trading loop starts).
- **3.1:** The startup path drives closed/qty-drift detection from `store.get_open_positions()` (DB rows) rather than `manager._positions`, because `startup_reconcile` is called in `bot.py::_readiness_gate` **before** `PositionManager.reconstruct_from_store()` runs (POS-05) — `manager._positions` is empty at that call site in production. A design that read `manager._positions` for both paths would have silently disabled cold-boot D-09 closed/qty-drift detection. This was caught by tracing `tests/position/test_manager.py::test_restart_reconciliation`, which drives `startup_reconcile(store, manager=None)` against a real seeded `StateStore` and asserts DB-level phase/qty changes — that test would have broken (or worse, silently no-op'd) under a naive `manager._positions`-only unification.
- **3.1:** The steady-state path keeps driving closed/qty-drift detection from `manager._positions` (unchanged from pre-refactor `reconcile_once`) because the existing `TestReconciliation` test suite mocks `manager._positions` directly (e.g. `test_reconcile_once_reprotects_closed_but_held`, `test_reconcile_once_qty_drift_adopts_broker_qty`) without a matching `store.get_open_positions()` return value on the accompanying `MagicMock()` store — reading from the DB side there would return an empty/unconfigured mock and silently skip the scenario under test.
- **3.1:** Orphan-adoption audit event names, alert-firing, and the `manager.adopt_orphan()` call are branched on `is_startup` inside the shared orphan loop (`drift_closed_by_broker`/`drift_orphan_adopted` + alerts for reconcile_once vs `reconcile_closed_by_broker`/`orphan_adopted` + no alerts + no `adopt_orphan()` call for startup_reconcile) — these are the only places behavior genuinely differs between the two paths; both existing audit-event assertions (`tests/gateway/test_gateway.py`, `tests/position/test_manager.py::test_restart_reconciliation`) require the distinction to be preserved exactly.
- **3.2:** `daily_bars_cache` defaults to `None` everywhere and `run_daily_scan` never passes one — the premarket scan runs once per trading day, so there's no caching benefit and no risk of a stray cache reference outliving that one call.
- **3.2:** The cache is a plain dict owned by `TradingBot` (`self._daily_bar_cache`), not a module-level singleton — keeps `bot/scanner/scanner.py`'s functions pure/testable (no hidden global state) per the codebase's immutable-config / no-mutable-singleton constraint (06.2-RESEARCH Open Question 3).

## Decisions Made

- **2.3:** Reused `bot.state.store.record_trade` (a pre-existing, already-tested writer previously called only by the backtester harness) instead of adding a duplicate `insert_trade(dict)` method as the SPEC's artifact list assumed. The actual bug was zero production callers on the live path, not a missing writer — matching the Ponytail "already in this codebase" rung.
- **2.4:** The retry+fallback in `ExecutionEngine` falls back to the last successfully-fetched bid/ask price *within the same order loop*, not bar-close data (there is no `bar_buffer` dependency on `ExecutionEngine`). A total outage on the very first price fetch (no fallback yet available) still raises `GatewayError`, which `_place_exit_order`'s pre-existing broad `except Exception: return 0` already handles as "no fill" — this preserves prior behavior for that edge case rather than introducing new cross-module bar-data plumbing.
- **2.4 (regression guard):** Also hardened the entry path (`_manage_entry_order`'s two `get_ask_price` call sites), which previously never raised (`get_ask_price` returned `0.0` on failure) and had zero exception handling around it. Left unguarded, the gateway's new raise-on-failure behavior would have propagated an unhandled exception into the bar-processing loop. Now treated as an entry abandon (resolves the pending_intent `EXPIRED`, matches existing D-05 semantics) — this is Rule 1/Rule 3 territory (a regression I was about to introduce), not scope creep.
- **2.7:** Scoped the exit-proxy fix strictly to `_trigger_stop_out` (both call sites), per the finding. The same `avg_fill_price`-as-entry-proxy imprecision exists in the `force_close` and `partial`-profit exit alert sites in the same file — logged in `deferred-items.md` rather than fixed, since neither has a natural "stop" reference to substitute and picking one is a design decision beyond this finding's scope.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `_evaluate_symbol`'s new staleness check crashed on a string `scan_date`**

- **Found during:** Task 6 (finding 2.6) — full-suite run after the initial fix
- **Issue:** The backtester harness (`backtester/harness.py::setup_day`) calls `_evaluate_symbol` with `scan_date` as a raw `"YYYY-MM-DD"` string in some paths, not always a `date` object. My first implementation did `scan_date - prior_date` directly, raising `TypeError: unsupported operand type(s) for -: 'str' and 'datetime.date'` and failing 3 backtester tests.
- **Fix:** Used the already-computed `scan_ts = pd.Timestamp(scan_date)` (existing normalization a few lines above) and compared `scan_ts.date() - prior_date` instead of the raw parameter.
- **Files modified:** `bot/scanner/scanner.py`
- **Commit:** `de06c7a` (Task 6 commit)

**2. [Rule 1 - Bug] Existing signal-engine cap tests broke after moving the cap-count source from the broker snapshot to the DB**

- **Found during:** Task 1 (finding 2.1) — full-suite run after the fix
- **Issue:** `test_concurrent_cap` and `test_blocked_signal_does_not_consume_pending` in `tests/signal/test_signal_engine.py` simulated "at cap" by returning a 3-row broker-snapshot DataFrame from the mocked gateway — exactly the pre-fix behavior finding 2.1 corrects. Post-fix, the cap count no longer reads the broker snapshot at all, so both tests started asserting the wrong thing (expected "blocked", but nothing in the DB meant the gate now passed).
- **Fix:** Updated both tests to seed the DB `positions` table (via a new `_insert_position_row` helper) with the "at cap" / "blocked" scenario instead of relying on the broker snapshot DataFrame.
- **Files modified:** `tests/signal/test_signal_engine.py`
- **Commit:** `a4b0d9b` (Task 1 commit)

**3. [Rule 1 - Bug] `test_restart_reconciliation` broke after adding `_initial_stop_pct` to `MoomooGateway.__init__`**

- **Found during:** Task 8 (finding 2.8) — full-suite run after the fix
- **Issue:** `tests/position/test_manager.py::test_restart_reconciliation` constructs a `MoomooGateway` via `object.__new__(MoomooGateway)` (bypassing `__init__` entirely) and sets a handful of attributes manually. It didn't set the new `_initial_stop_pct` attribute, so `_compute_orphan_stop` raised `AttributeError` when the test's `startup_reconcile` path hit an orphan.
- **Fix:** Added `gw._initial_stop_pct = 1.0` alongside the test's other manual attribute assignments.
- **Files modified:** `tests/position/test_manager.py`
- **Commit:** `90efa24` (Task 8 commit)

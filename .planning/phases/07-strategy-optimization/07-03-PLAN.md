<objective>
Move stop invalidation from 5m bar-close to tick/broker granularity (RISK-TICK-STOP). Add `place_stop_order` to the gateway (the sole EXEC-02 market-order exception, D-01), arm a broker-side Stop-Market protective order at entry-fill time, cancel-replace it on every trail ratchet to mirror `trail_stop` (D-04), and build the D-02 bot-side quote-tick fallback selected by the `use_broker_stop_orders` config flag for accounts (e.g. SIMULATE) that may not honor stop orders. The existing bar-close stop check stays as a redundant backstop (D-03).

Purpose: The June fat-tail losses came from stops that only fired at the next 5m bar close, letting price run well past 1R. A broker-side stop (which also survives a bot/OpenD crash) or a tick-level quote monitor closes that window so realized stop-outs converge toward ~1R. Because SIMULATE stop-order support is empirically unverified (RESEARCH Finding C-3, Open Question 1), both paths ship behind one config flag; the operator's live SIMULATE test selects the default.

Output: `Gateway.place_stop_order` + quote subscription/handler; `PositionManager.arm_stop_protection` / `_sync_broker_stop` / `_on_quote`; a one-line post-fill hook in `bot.service.bot`; extended gateway/manager/bot tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bot → Moomoo/OpenD order API | Every order (including the new stop) crosses into the broker; the paper-only invariant must hold |
| broker quote push → PositionManager | Untrusted tick data drives an immediate exit decision in the fallback path |
| PositionState.broker_stop_order_id → DB | Order-id state must survive restart to avoid orphaned/duplicate stops |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-09 | Elevation | EXEC-02 amendment could leak a real-money or wrong-type order path | mitigate | place_stop_order reuses self.cfg.trd_env (SIMULATE) exactly like place_order; it is the single OrderType.STOP path; SAFE-01 paper guard at startup is unchanged; no TrdEnv.REAL literal introduced |
| T-07-10 | Tampering | Wrong trd_side on a protective stop opens exposure instead of closing (Pitfall 7) | mitigate | Long-only strategy: place_stop_order callers pass TrdSide.SELL; asserted in tests |
| T-07-11 | Spoofing | Spoofed/erroneous quote tick triggers a false exit in the fallback path | mitigate | Fallback fires only on bid<=trail_stop for a broker-verified open position; one-shot guard prevents repeated fires; bar-close FSM remains the corroborating backstop (D-03) |
| T-07-12 | Repudiation | Stop placement not auditable | mitigate | place_stop_order writes append_audit event="stop_order_placed" (extends ~/.futu_trade_audit.jsonl, SAFE-05) |
| T-07-13 | Denial of Service | Cancel-replace no-stop window exploited by a flash move (Pitfall 5) | accept | Accepted cost per D-04; bar-close stop check is the redundant backstop (D-03); window is sub-second |
| T-07-SC | Tampering | Supply-chain: dependency installs | accept | No new packages installed this phase (moomoo-api already vetted) |
</threat_model>

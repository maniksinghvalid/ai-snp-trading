<objective>
Build the RVOL-TOD data production path: the cumulative-session-volume signal that the fixed intraday RVOL gate will consume. Add a `cum_volume` field to `BarEvent`, make `BarAggregator` accumulate per-code running session volume (reset each session), add a 5m-history downloader to the scanner's fetcher, and compute + persist a 14-session time-of-day cumulative-volume baseline per scan candidate into the `tod_baselines` table at premarket scan.

Purpose: The current RVOL denominator compares a single 5m bar's volume against a full-day average, which almost never reaches 2.0 (RESEARCH Finding C-4). This plan produces both halves of the corrected comparison — the live cumulative volume (numerator, via BarAggregator) and the time-of-day 14-day average cumulative volume (denominator, via the scanner) — so plan 07-05 can wire the fair I3 gate. This plan produces data only; it does not change the signal decision (that is 07-05).

Output: `BarEvent.cum_volume`; `BarAggregator._session_volume`; `fetcher.download_intraday_5m`; `scanner._compute_tod_baselines` + its store write; extended aggregator/fetcher/scanner tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| yfinance (external market data) → scanner | Untrusted third-party OHLCV; partial/degraded data must not silently corrupt baselines |
| K_5M broker push → BarAggregator | Volume field semantics (per-bar vs cumulative) drive the RVOL numerator |
| scanner → tod_baselines table | Computed baselines drive a live trading gate downstream |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-05 | Tampering | Degraded/partial yfinance 5m batch produces a skewed baseline | mitigate | download_intraday_5m reuses the existing degradation gate (threshold + abort/partial events); per-candidate compute is wrapped so a bad symbol logs and is skipped, not stored |
| T-07-06 | Spoofing | UTC vs ET bucket mismatch stores baselines under the wrong clock time → gate silently disabled | mitigate | ET-localize the index before bucketing; scan_date keyed on now_et() (Pitfall 4); test asserts ET bucketing |
| T-07-07 | Tampering | Cross-session volume carryover inflates cum_volume | mitigate | reset_session() clears _session_volume; test proves reset (Pitfall 1) |
| T-07-08 | Denial of Service | Per-candidate 5m downloads exhaust yfinance rate limits | accept | Bounded concurrency (threads=5) reused; TOD download runs once at premarket only, not per intraday rescan (RESEARCH Open Q4) |
| T-07-SC | Tampering | Supply-chain: dependency installs | accept | No new packages installed this phase (yfinance/pandas already vetted in Phase 2) |
</threat_model>
